Lesson 2: Blind / Uninformed Search — BFS

Your workbook now moves from State Space Representation to Blind / Uninformed Search, beginning with Breadth First Search (BFS).

1. First understand: What is Search?

Before BFS, ask students:

"We know the starting state and the goal state. But how do we find the path between them?"

Answer: We use a search technique.
Key Idea: We know the Initial State and the Goal State. A search algorithm determines the sequence of valid transitions needed to navigate from the start to the target.

There are different search techniques. For Assignment 1, the important ones are:

Search | ├── BFS ├── DFS └── DLS

2. What does "Blind Search" mean?

Blind / Uninformed Search: A search technique that does not use additional information or a heuristic about how close a state is to the goal.
Intuition: A blind search algorithm does not possess an internal map or heuristic evaluation of closeness to the target. It systematically expands and explores valid successor states purely by traversal order: "I do not know which move is best beforehand; I test each reachable state methodically."

3. BFS — Breadth First Search

Now introduce the full form: BFS = Breadth First Search

Simple Definition: BFS is a search algorithm that explores nodes level by level.
Key Traversal Rule: BFS explores every node on depth level d completely before expanding any child node at depth d + 1.

4. What is "Level by Level"?

A / \ B C / \ / \ D E F G

Now divide it into levels:

Level 0 A Level 1 B C Level 2 D E F G

BFS first visits A, then B C, then D E F G.

BFS traversal: A → B → C → D → E → F → G

Level Progression: All nodes in Level 0 are expanded first, followed by all nodes in Level 1, then all nodes in Level 2.

5. What is a Node?

A node is an individual element/state in the search tree. In our example, A, B, C, D, etc. are nodes.

Node Definition: An individual element or discrete configuration state in the search space is called a Node.

6. What is a Tree?

A tree is a structure in which nodes are connected in a hierarchical manner.

A → Parent B,C → Children of A D,E → Children of B F,G → Children of C

7. The MOST IMPORTANT Concept — Queue

"BFS uses a Queue." It uses a FIFO (First In, First Out) approach.

8. What is a Queue?

Imagine students standing in a queue. Who gets served first? Student A, because A entered first.

FIFO — First In, First Out
Queue Analogy: Think of customers standing in line at a service counter. The person who arrived first is attended to first. Hence: FIFO = First In, First Out.

9. Why Does BFS Use Queue?

Queue processing steps automatically process nodes level by level:

  • Start: Queue = [A]
  • Remove A, Add children: Queue = [B, C]
  • Remove B, Add children: Queue = [C, D, E]
  • Remove C, Add children: Queue = [D, E, F, G]

10. BFS Step-by-Step

Initial State = A | Goal = G

Step 1: Visit A. Queue = [B, C] Step 2: Visit B. Queue = [C, D, E] Step 3: Visit C. Queue = [D, E, F, G] Step 4: Visit D. Step 5: Visit E. Step 6: Visit F. Step 7: Visit G. (Goal found! STOP)
Important distinction:
Traversal order: A → B → C → D → E → F → G
Solution path to G: A → C → G

11. BFS Algorithm

1. Start with the initial state. 2. Put the initial state into the queue. 3. Remove the first state from the queue. 4. Check whether it is the goal state. 5. If it is the goal, stop. 6. Otherwise, generate its successor states. 7. Add unvisited successors to the queue. 8. Repeat until the goal is found or queue is empty.
Algorithmic Execution Steps:
1. Initialize search with the starting state.
2. Push initial state into the FIFO Queue.
3. Dequeue the front state.
4. Check if current state satisfies the goal condition.
5. If goal is reached → terminate successfully.
6. Otherwise, generate all valid successor states.
7. Enqueue unvisited successors to the queue.
8. Repeat until the goal is found or the queue is exhausted.

12. What is a Successor?

States generated from another state by applying an action.

Successor State: Any state directly produced by applying an operator/action to the current state is called a Successor State.

13. BFS in One Simple Diagram (Board Layout)

Practical 1 Monkey-Banana Problem using Breadth-First Search (BFS)

4. Complete Python Implementation

from collections import deque # Step 1: Initialize the FIFO queue with the initial state S0 queue = deque(["Monkey at Door"]) # Step 2: Track visited states to prevent redundant cycles visited = [] # Step 3: Run the BFS loop while the queue has pending states while queue: # Remove the front state (FIFO: First-In, First-Out) state = queue.popleft() if state not in visited: visited.append(state) print(state) # Transition logic based on current state if state == "Monkey at Door": queue.append("Monkey at Box") elif state == "Monkey at Box": queue.append("Box Under Banana") elif state == "Box Under Banana": queue.append("Monkey Climbs Box") elif state == "Monkey Climbs Box": queue.append("Monkey Gets Banana") elif state == "Monkey Gets Banana": print("\nGoal: Banana Obtained!") break

5. Line-by-Line Code Explanation

  • from collections import deque
    Imports the double-ended queue class from Python's standard library. Unlike standard Python lists which require O(n) time to remove elements from the start, deque executes popleft() in optimal O(1) constant time.
  • queue = deque(["Monkey at Door"])
    Initializes the search frontier with the single starting state S0.
  • visited = []
    An explored list tracking every expanded state, guaranteeing no state is processed multiple times.
  • while queue:
    Continues the search frontier exploration as long as elements remain in the queue.
  • state = queue.popleft()
    Pulls the oldest element from the front, enforcing strict BFS FIFO ordering.
  • if state == "Monkey Gets Banana": ... break
    Validates whether the extracted state satisfies the goal condition. If true, prints the success message and terminates the algorithm.

7. Essential Viva-Voce Questions

  1. What type of search algorithm is BFS?
    Answer: It is an Uninformed (Blind) Search algorithm because it traverses the state space without using any heuristic or cost-to-goal estimation.
  2. Why does BFS require a Queue instead of a Stack?
    Answer: A Queue strictly enforces FIFO (First-In, First-Out), ensuring nodes are expanded level-by-level (shallowest nodes first). A Stack implements LIFO, which turns the search into DFS (Depth-First Search).
  3. What is the state transition sequence in the Monkey-Banana problem?
    Answer: S0 (At Door) → S1 (At Box) → S2 (Box Under Banana) → S3 (Climb Box) → S4 (Grab Banana).
  4. What is the time and space complexity of BFS?
    Answer: Both time complexity and space complexity are O(bd), where b is the branching factor and d is the depth of the shallowest goal.

Slip 2, 13 Practical 2: Water Jug Problem using Breadth-First Search (BFS)

1. Problem Definition & Physical Setup

You are given two unmeasured water jugs with fixed maximum capacities:

  • Jug X: Capacity of 4 Liters.
  • Jug Y: Capacity of 3 Liters.
  • An infinite supply of tap water and a ground drain are available. Neither jug has measurement markings.
  • Initial State: Both jugs are completely empty: (0, 0).
  • Goal State: Obtain exactly 2 Liters of water in either jug: x == 2 or y == 2 (typically reaching (4, 2) or (2, 0)).
Algorithmic Strategy: Why use BFS for the Water Jug problem? Because BFS systematically explores every reachable configuration level by level, it is guaranteed to discover the solution sequence with the minimum possible number of pouring operations (shortest path).

2. State Space Representation & Production Rules

A state is formally defined as an ordered pair (x, y), where x ∈ {0, 1, 2, 3, 4} represents liters in the 4L jug, and y ∈ {0, 1, 2, 3} represents liters in the 3L jug.

Rule # Operator / Action Precondition Transition: (x, y) → Next State Plain English Meaning
R1 Fill 4L Jug x < 4 (4, y) Fill the 4-Liter jug to maximum capacity from tap
R2 Fill 3L Jug y < 3 (x, 3) Fill the 3-Liter jug to maximum capacity from tap
R3 Empty 4L Jug x > 0 (0, y) Dump all water from 4-Liter jug onto the ground
R4 Empty 3L Jug y > 0 (x, 0) Dump all water from 3-Liter jug onto the ground
R5 Pour 4L → 3L x > 0 and y < 3 (max(0, x - (3 - y)), min(3, x + y)) Pour from 4L into 3L until 3L is completely full
R6 Pour 3L → 4L y > 0 and x < 4 (min(4, x + y), max(0, y - (4 - x))) Pour from 3L into 4L until 4L is completely full

3. State-Space Search Tree & Solution Path

(0, 0) [Initial: Both Empty] / \ (4, 0) (0, 3) <-- Selected by BFS frontier / \ (3, 0) (0, 0)* [Visited] | (3, 3) [Fill 3L] | (4, 2) <-- GOAL STATE FOUND! (2L in 3L jug)

Shortest Solution Sequence:

Step 0: (0, 0) --> Start with both jugs empty Step 1: (0, 3) --> Fill the 3-Liter jug completely Step 2: (3, 0) --> Pour all 3 Liters from 3L jug into 4L jug Step 3: (3, 3) --> Fill the 3-Liter jug completely again Step 4: (4, 2) --> Pour 1 Liter from 3L into 4L until 4L is full (Leaving exactly 2L in 3L jug!)

4. Complete Python Implementation

from collections import deque # Double-ended queue for BFS (O(1) popleft) def water_jug(): # Set to store visited states and prevent infinite cyclic loops visited = set() # Queue stores tuples of: (current_state, path_taken_so_far) queue = deque([((0, 0), [(0, 0)])]) while queue: (x, y), path = queue.popleft() # FIFO: Remove shallowest unvisited state if (x, y) in visited: continue # Skip states that have already been explored visited.add((x, y)) # Goal Condition: Check if either jug contains exactly 2 Liters if x == 2 or y == 2: print("Solution Path:") for state in path: print(state) return # Generate all 6 possible production moves (Successor States) states = [ (4, y), # 1. Fill 4L jug (x, 3), # 2. Fill 3L jug (0, y), # 3. Empty 4L jug (x, 0), # 4. Empty 3L jug (max(0, x - (3 - y)), min(3, x + y)), # 5. Pour 4L -> 3L until full (min(4, x + y), max(0, y - (4 - x))) # 6. Pour 3L -> 4L until full ] # Enqueue unvisited valid successor states for s in states: if s not in visited: queue.append((s, path + [s])) if __name__ == "__main__": water_jug()

Expected Terminal Output

Solution Path: (0, 0) (0, 3) (3, 0) (3, 3) (4, 2)

  • Initial State: (0, 0).
  • Goal State: x == 2 or y == 2 (reached at (4, 2)).
  • Data Structure: FIFO Queue (collections.deque) and Visited Set.

Essential Viva-Voce Questions

  1. How is the state space bounded in this problem?
    Answer: The 4L jug can have 5 values (0..4) and the 3L jug can have 4 values (0..3). Total discrete states = 5 × 4 = 20 states maximum.
  2. What mathematical condition determines if a Water Jug problem has a solution?
    Answer: By Bézout's Identity, a solution exists if and only if the target quantity is a multiple of the Greatest Common Divisor of the two jug capacities: target % gcd(cap1, cap2) == 0. Here, gcd(4, 3) = 1, and 2 % 1 == 0, so a solution is guaranteed.
  3. Why is a visited set critical in state-space BFS?
    Answer: Without a visited set, reversible actions (like filling and emptying repeatedly) create closed cycles, causing an infinite loop and memory exhaustion.

Slip 15 Practical 3: State-Space Search using Depth-First Search (DFS)

1. Theory & Working Mechanism of DFS

Depth-First Search (DFS) is an uninformed search strategy that systematically progresses as deeply as possible along each branch before backtracking.

Algorithmic Strategy: Depth-First Search (DFS) systematically pursues each branch to its maximum depth. If a dead-end state is reached, it backtracks to the previous node to explore unexplored branches using a LIFO Stack to minimize memory consumption.

2. Master Comparison: BFS vs DFS

Evaluation Criteria Breadth-First Search (BFS) Depth-First Search (DFS)
Data Structure Queue (FIFO) — First In, First Out Stack (LIFO) — Last In, First Out / System Call Stack
Exploration Pattern Level-by-level (horizontal / broad) Path-by-path (vertical / deep)
Space Complexity O(bd) — Very High (stores entire frontier) O(b · m) — Extremely Low (stores only active path)
Time Complexity O(bd) O(bm) (where m is max depth)
Optimality Guaranteed optimal for uniform step cost Not optimal (may return a long path when a short one exists)
Completeness Complete (always finds goal if it exists) Incomplete if infinite branches or unvisited cycles exist

4. Complete Python Implementation

# Graph adjacency representation for State-Space Search graph = { 1: [2, 3], 2: [1, 4], 3: [1, 5], 4: [2, 5, 6], 5: [3, 4, 6], 6: [4, 5] } def dfs_state_space(graph, start): visited = set() # Tracks already explored nodes to avoid cycles stack = [start] # Stack implements LIFO (Last-In, First-Out) traversal = [] # Stores the sequential visit order print("Starting DFS State-Space Search...") while stack: node = stack.pop() # Pull the most recently pushed node if node not in visited: visited.add(node) traversal.append(str(node)) print(f"Visited: {node}") # Sort neighbors in descending order so smaller numbers are popped first neighbors = sorted(graph[node], reverse=True) for neighbor in neighbors: if neighbor not in visited: stack.append(neighbor) # Push neighbor onto LIFO stack print("-" * 30) print("Final DFS Traversal Path:") print(" -> ".join(traversal)) if __name__ == "__main__": dfs_state_space(graph, 1)

Essential Viva-Voce Questions

  1. Why does DFS have a much lower memory footprint than BFS?
    Answer: BFS must keep the entire breadth-level frontier in memory (exponential $O(b^d)$). In contrast, DFS only stores the single active path from the root down to the current node, needing only $O(b \cdot m)$ space.
  2. What is the purpose of reversing neighbor order when pushing to the stack?
    Answer: A stack is LIFO. By sorting neighbors in reverse (e.g. pushing 3 then 2), the smallest numeric vertex (2) sits at the top of the stack and is popped first.
  3. What is Depth-Limited Search (DLS)?
    Answer: DLS is DFS equipped with a predefined cutoff depth limit $l$. It prevents DFS from entering infinite loops on infinitely deep paths.

Slip 1, 7 Practical 4: A* Search Algorithm (Informed / Heuristic Search)

1. Theory: What Makes A* "Informed"?

Uninformed searches (BFS, DFS) operate blindly without knowing if a step brings them closer to the target. A* Search is an Informed (Heuristic) Search that uses domain knowledge to direct the search directly toward the goal.

The Fundamental A* Evaluation Function

f(n) = g(n) + h(n)

  • g(n): The exact path cost incurred so far from the Start Node to current node n.
  • h(n): The heuristic estimated cost from current node n to the Goal Node.
  • f(n): The total estimated cost of the cheapest solution path passing through node n.
Algorithmic Strategy: A* Search intelligently balances the past accumulated path cost $g(n)$ with the future estimated cost $h(n)$ through the evaluation formula $f(n) = g(n) + h(n)$. A Min-Heap Priority Queue guarantees that the frontier node with the lowest overall estimated cost is always explored first.

2. Heuristic Admissibility & Optimality Condition

Admissibility Rule: A heuristic $h(n)$ is admissible if it never overestimates the true minimal cost to reach the goal, i.e., $0 \le h(n) \le h^*(n)$ for all $n$, where $h^*(n)$ is the true actual cost.

Theorem: If $h(n)$ is admissible, the A* algorithm is guaranteed to find the optimal shortest path.

5. Complete Python Implementation

import heapq # Python Min-Heap Priority Queue module # Graph adjacency representation: node -> {neighbor: edge_cost} graph = { 'A': {'B': 1, 'C': 4}, 'B': {'D': 2, 'E': 5}, 'C': {'F': 3}, 'D': {'G': 3}, 'E': {'G': 1}, 'F': {'G': 2}, 'G': {} # Goal node } # Heuristic estimated cost to goal G h = { 'A': 6, 'B': 5, 'C': 4, 'D': 3, 'E': 2, 'F': 2, 'G': 0 } def a_star(start, goal): # Priority Queue stores tuples of: (f_score, g_cost, current_node, path) queue = [(h[start], 0, start, [start])] visited = set() while queue: # heappop always removes the element with the SMALLEST f value f, g, node, path = heapq.heappop(queue) if node in visited: continue visited.add(node) print("Visiting:", node) # Goal check if node == goal: print("\nShortest Path:", " -> ".join(path)) print("Total Cost:", g) return # Expand neighbors for neighbour, cost in graph[node].items(): new_g = g + cost # Exact cost to reach neighbour new_f = new_g + h[neighbour] # f = g + h formula # Push candidate path into priority queue heapq.heappush(queue, (new_f, new_g, neighbour, path + [neighbour])) if __name__ == "__main__": a_star('A', 'G')

Essential Viva-Voce Questions

  1. What happens if the heuristic h(n) = 0 for all nodes?
    Answer: When $h(n) = 0$, $f(n) = g(n)$, and A* becomes identical to Dijkstra's Algorithm / Uniform Cost Search (UCS).
  2. What is the difference between an admissible heuristic and a consistent heuristic?
    Answer: An admissible heuristic never overestimates the true cost to the goal ($h(n) \le h^*(n)$). A consistent (monotonic) heuristic additionally obeys the triangle inequality: $h(n) \le c(n, a, n') + h(n')$.
  3. Why does A* use a Priority Queue?
    Answer: A Priority Queue guarantees that the frontier node with the lowest total estimated cost $f(n)$ is always expanded next.

Slip 8, 19 Practical 5: 8-Puzzle Problem using A* Search

1. Problem Formulation

The 8-puzzle is a classic sliding tile problem played on a 3×3 board with 8 numbered tiles and 1 blank space (represented by 0):

  • Initial State: (1, 2, 3, 4, 0, 6, 7, 5, 8)
  • Goal State: (1, 2, 3, 4, 5, 6, 7, 8, 0)
  • Operators: Slide the blank tile 0 Up, Down, Left, or Right within grid boundaries.
Initial State: Goal State: +---+---+---+ +---+---+---+ | 1 | 2 | 3 | | 1 | 2 | 3 | +---+---+---+ +---+---+---+ | 4 | 0 | 6 | | 4 | 5 | 6 | +---+---+---+ +---+---+---+ | 7 | 5 | 8 | | 7 | 8 | 0 | +---+---+---+ +---+---+---+

2. Heuristics: Misplaced Tiles vs Manhattan Distance

Heuristic Metric Definition Admissible? Quality / Efficiency
h1: Misplaced Tiles Number of tiles that are not in their final goal position Yes ($h_1 \le h^*$) Coarse estimate; explores many redundant states
h2: Manhattan Distance Sum of horizontal and vertical distances of each tile from its goal coordinates: $$\sum_{i=1}^{8} |row_i - goal\_row_i| + |col_i - goal\_col_i|$$ Yes ($h_2 \le h^*$) Superior & Dominates h1: $h_2(n) \ge h_1(n)$ for all states, expanding far fewer nodes!
Algorithmic Strategy: In the 8-puzzle, the Manhattan Distance sums the exact horizontal and vertical steps each tile must take to reach its goal position. Because tiles cannot jump diagonally, this provides a strictly tighter, more informed bound than merely counting misplaced tiles, dramatically reducing explored states.

3. Complete Python Implementation

import heapq # Goal state configuration (0 represents the empty space) goal = (1, 2, 3, 4, 5, 6, 7, 8, 0) def heuristic(state): # Calculates the Manhattan Distance of all numbered tiles from their goal slots distance = 0 for i in range(9): value = state[i] if value != 0: # Ignore the blank tile goal_pos = goal.index(value) # Row distance + Column distance distance += abs(i // 3 - goal_pos // 3) distance += abs(i % 3 - goal_pos % 3) return distance def neighbours(state): result = [] zero = state.index(0) # Locate position of blank space row, col = zero // 3, zero % 3 # Moves: Up, Down, Left, Right (dr, dc) moves = [(-1, 0), (1, 0), (0, -1), (0, 1)] for dr, dc in moves: nr, nc = row + dr, col + dc if 0 <= nr < 3 and 0 <= nc < 3: # Keep moves inside 3x3 grid new_zero = nr * 3 + nc new_state = list(state) # Swap blank space with adjacent neighbor tile new_state[zero], new_state[new_zero] = new_state[new_zero], new_state[zero] result.append(tuple(new_state)) return result def astar(start): # Priority Queue stores: (f_score, g_cost, state, path) queue = [(heuristic(start), 0, start, [start])] visited = set() while queue: f, g, state, path = heapq.heappop(queue) if state in visited: continue visited.add(state) if state == goal: print("Solution:") for step in path: print(step) return # Generate neighbor states for next_state in neighbours(state): new_g = g + 1 new_f = new_g + heuristic(next_state) heapq.heappush(queue, (new_f, new_g, next_state, path + [next_state])) if __name__ == "__main__": start = (1, 2, 3, 4, 0, 6, 7, 5, 8) astar(start)

    Answer: Each legal move of a tile changes its Manhattan distance by at most 1. Hence, the true number of remaining moves can never be less than the total Manhattan distance.
  2. How many total permutations exist in an 8-puzzle and are all solvable?

Slip 3, 8, 11 Practical 6: Minimax Search & Alpha-Beta Pruning

1. Adversarial Search Concepts (Two-Player Games)

In two-player zero-sum perfect information games (such as Chess or Tic-Tac-Toe), two players compete against each other:

  • MAX Player: Aims to maximize their final payoff/utility.
  • MIN Player: Aims to minimize MAX's payoff (maximizing their own utility).

2. Why Minimax Needs Optimization: The Exponential Explosion

Standard Minimax searches all game tree paths to maximum depth $m$. With branching factor $b$, it visits $O(b^m)$ nodes. In chess ($b \approx 35$), exploring even 5 plies requires examining millions of states.

3. The Alpha-Beta Pruning Solution

Alpha (α) and Beta (β) Bounds:
  • α (Alpha): The best (highest) guaranteed score for MAX along the current path (initialized to $-\infty$).
  • β (Beta): The best (lowest) guaranteed score for MIN along the current path (initialized to $+\infty$).
  • The Pruning Condition: Whenever α ≥ β, stop evaluating remaining sibling branches (Prune / Cutoff).
Algorithmic Strategy: Alpha-Beta Pruning speeds up Minimax game tree evaluation by skipping branches that cannot influence the final decision. Once the condition $\alpha \ge \beta$ is met, neither MAX nor MIN will choose to enter that sub-branch, allowing the search to safely prune it.

4. Pruning Tree Diagram

Root (MAX) [Returns: 3] / \ B (MIN) C (MIN) / \ / \ [3] [5] [2] [9] (PRUNED if alpha >= beta!) ^ MIN chooses 3; MAX will get at least 3. When C evaluates 2, MIN can force ≤ 2. Since MAX already has 3, branch with [9] is PRUNED!

5. Complete Python Implementation

import math # Game tree structure with leaf evaluations tree = { 'A': ['B', 'C'], 'B': ['D', 'E'], 'C': ['F', 'G'], 'D': 3, 'E': 5, 'F': 2, 'G': 9 } # 1. Standard Minimax (Explores all paths) def minimax(node, maximizing): if isinstance(tree[node], int): return tree[node] # Return leaf score values = [minimax(child, not maximizing) for child in tree[node]] return max(values) if maximizing else min(values) # 2. Alpha-Beta Pruning (Skips redundant subtrees) def alpha_beta(node, alpha, beta, maximizing): if isinstance(tree[node], int): return tree[node] if maximizing: # MAX Player's turn value = -math.inf for child in tree[node]: value = max(value, alpha_beta(child, alpha, beta, False)) alpha = max(alpha, value) if alpha >= beta: print(f"Pruning remaining branches under node {node} (alpha={alpha} >= beta={beta})") break # Pruning cutoff return value else: # MIN Player's turn value = math.inf for child in tree[node]: value = min(value, alpha_beta(child, alpha, beta, True)) beta = min(beta, value) if alpha >= beta: print(f"Pruning remaining branches under node {node} (alpha={alpha} >= beta={beta})") break # Pruning cutoff return value if __name__ == "__main__": print("Minimax Result: ", minimax('A', True)) print("Alpha-Beta Result:", alpha_beta('A', -math.inf, math.inf, True))

  • Alpha (α) Initial Value: $-\infty$ (Best choice for MAX).
  • Beta (β) Initial Value: $+\infty$ (Best choice for MIN).
  • Pruning Criterion: $\alpha \ge \beta$.
  • Efficiency: In the best case, Alpha-Beta halves the effective search depth complexity from $O(b^m)$ to $O(b^{m/2})$.

Essential Viva-Voce Questions

  1. Does Alpha-Beta Pruning alter the final move chosen compared to Minimax?
    Answer: Absolutely not. Alpha-Beta Pruning produces the mathematically identical result as Minimax; it only cuts away branches that cannot possibly affect the final decision.
  2. What is the best-case time complexity of Alpha-Beta Pruning?
    Answer: With perfect move ordering (best moves evaluated first), time complexity drops to $O(b^{m/2})$, effectively doubling the searchable lookahead depth.

Slip 2, 7 Practical 7: Constraint Satisfaction Problem (CSP) — Graph & Map Coloring

1. Formal Definition of CSP

A Constraint Satisfaction Problem (CSP) consists of three fundamental components:

  • Variables (X): A finite set of variables: $\{X_1, X_2, \dots, X_n\}$. (e.g., regions or graph vertices $1, 2, 3, 4, 5$).
  • Domains (D): A set of allowable values for each variable: $\{D_1, D_2, \dots, D_n\}$. (e.g., colors $\{\text{Blue, Green, Yellow, Red, Purple}\}$).
  • Constraints (C): Rules restricting valid combinations of variable assignments. (e.g., adjacent regions cannot have identical colors).
Algorithmic Strategy: In a Constraint Satisfaction Problem (CSP), the goal is to discover a complete variable-value assignment that adheres to all restrictions simultaneously. For Map Coloring, adjacent regions cannot share colors; when an assignment causes a conflict, Backtracking undoes the step and tries the next candidate.

2. Pentagon / Graph Coloring Setup

Graph Coloring (Adjacent nodes must have different colors): (1) / \ (2)---(5) | | (3)---(4)

3. Complete Python Implementation (Backtracking Algorithm)

# Graph adjacency: which nodes share an edge graph = { 1: [2, 3, 4, 5], 2: [1, 3, 4, 5], 3: [1, 2, 4, 5], 4: [1, 2, 3, 5], 5: [1, 2, 3, 4] } nodes = [1, 2, 3, 4, 5] available_colors = ['Blue', 'Green', 'Yellow', 'Red', 'Purple'] node_colors = {} # Stores final variable assignments: {node: color} def solve_csp(node_index): # Base Case: All nodes have been successfully colored if node_index == len(nodes): return True current_node = nodes[node_index] # Try each available color for color in available_colors: # Check constraint safety against all connected neighbors is_safe = True for neighbor in graph[current_node]: if neighbor in node_colors and node_colors[neighbor] == color: is_safe = False # Conflict detected! break if is_safe: node_colors[current_node] = color # Assign color # Recurse to next unassigned node if solve_csp(node_index + 1): return True # BACKTRACK: If dead end encountered, unassign color and try next del node_colors[current_node] return False # Trigger backtracking to previous caller if __name__ == "__main__": print("Starting Backtracking Algorithm for CSP...") if solve_csp(0): print("Final Solution Found!") for node in nodes: print(f"Node {node} is colored {node_colors[node]}") else: print("No solution possible.")

Essential Viva-Voce Questions

  1. What is the difference between standard state-space search and CSP?
    Answer: In standard search, states are atomic "black boxes" evaluated along a path to the goal. In CSP, states are explicitly structured as variable-value assignments, and success is defined solely by satisfying all constraints.
  2. What are MRV and LCV heuristics in CSP?
    Answer: MRV (Minimum Remaining Values) picks the variable with the fewest legal values remaining ("fail-first"). LCV (Least Constraining Value) selects the value that leaves the most options open for neighboring variables.

Slip 11, 15 Practical 8: Knowledge Representation & Backward Chaining

1. Forward vs Backward Chaining

Characteristic Forward Chaining (Data-Driven) Backward Chaining (Goal-Driven)
Starting Point Starts with known facts Starts with a hypothetical goal
Direction Bottom-up: Facts → Rules → Conclusions Top-down: Goal → Sub-goals → Verified Facts
Ideal For Real-time monitoring, automated synthesis Medical diagnosis, debugging, fault finding
Algorithmic Strategy: Backward Chaining is a top-down, goal-directed reasoning approach. Starting with a candidate hypothesis, the inference engine works in reverse through rule implications to determine whether the necessary supporting premises can be verified from base facts.

2. Complete Python Implementation

# Known verified facts in Knowledge Base facts = {"rain"} # Logical Rules: conclusion -> [required premises] rules = { "wet_ground": ["rain"], "slippery": ["wet_ground"], "dangerous": ["slippery"] } def backward_chaining(goal): # Base Case: Goal is already a verified fact if goal in facts: return True # If no rule concludes this goal, it cannot be proved if goal not in rules: return False # Check if all sub-conditions of the rule can be recursively proved for condition in rules[goal]: if backward_chaining(condition): facts.add(goal) # Add newly proven assertion to facts return True return False if __name__ == "__main__": goal = "dangerous" if backward_chaining(goal): print("Goal proved:", goal) else: print("Goal cannot be proved")

🎯 10. Ultimate Viva-Voce Question Bank (Top 20 Questions)

  1. What are the 5 essential components of an AI search problem?
    Answer: Initial State, Goal State, State Space, Operators/Actions, and Path Cost.
  2. What is the difference between informed and uninformed search?
    Answer: Uninformed search relies solely on state generation order without knowing proximity to the goal. Informed search utilizes heuristic functions $h(n)$ to estimate remaining distance.
  3. Why does BFS find the shortest path in unweighted graphs?
    Answer: It explores nodes level by level in strict FIFO queue order, guaranteeing that the shallowest goal is reached first.
  4. What is the purpose of the collections.deque module in Python?
    Answer: Standard Python lists take $O(n)$ time to remove elements from index 0. collections.deque executes popleft() in constant $O(1)$ time.
  5. Explain the formula $f(n) = g(n) + h(n)$ in A* search.
    Answer: $g(n)$ is the true known cost from start to $n$; $h(n)$ is the estimated cost from $n$ to goal; $f(n)$ is total estimated cost.
  6. What does it mean for a heuristic to be admissible?
    Answer: It must never overestimate the actual true minimal cost to the goal ($h(n) \le h^*(n)$).
  7. What is Manhattan distance?
    Answer: The sum of absolute differences in row and column coordinates: $|x_1 - x_2| + |y_1 - y_2|$.
  8. Why does Manhattan distance dominate misplaced tiles in the 8-puzzle?
    Answer: Every misplaced tile is at least 1 move away, meaning Manhattan distance is always greater than or equal to misplaced tiles, providing tighter pruning while staying admissible.
  9. What is Alpha-Beta Pruning?
    Answer: An optimization for Minimax that eliminates branches whenever $\alpha \ge \beta$, where $\alpha$ is MAX's guaranteed score and $\beta$ is MIN's guaranteed score.
  10. What is the cutoff condition in Alpha-Beta Pruning?
    Answer: $\alpha \ge \beta$.
  11. What is a Constraint Satisfaction Problem (CSP)?
    Answer: A problem framed in terms of Variables, Domains, and Constraints, where the goal is to find valid variable assignments satisfying all constraints.
  12. What is the difference between Forward and Backward Chaining?
    Answer: Forward Chaining is data-driven (from facts to conclusion). Backward Chaining is goal-driven (from hypothesis back to supporting facts).
  13. What is the time complexity of BFS?
    Answer: $O(b^d)$, where $b$ is the branching factor and $d$ is the goal depth.
  14. What is the space complexity of DFS?
    Answer: $O(b \cdot m)$, where $m$ is the maximum tree depth.
  15. What happens if the heuristic in A* is $h(n) = 0$?
    Answer: It degenerates into Dijkstra's Algorithm / Uniform Cost Search.
  16. Why is a visited set essential in graph search?
    Answer: To prevent infinite loops caused by circular paths and redundant state expansions.
  17. In the Water Jug problem, what does max(0, x - (3 - y)) calculate?
    Answer: The remaining water in the 4L jug after pouring into the 3L jug until the 3L jug is filled to capacity (3L).
  18. What is a zero-sum game?
    Answer: A game where the algebraic sum of payoffs for all players is zero; one player's gain is the exact loss of the opponent.
  19. Why does A* search use a Priority Queue?
    Answer: To always retrieve the frontier state with the minimum $f(n)$ value in logarithmic time.
  20. Can DFS get trapped in an infinite loop?
    Answer: Yes, if the state space contains infinite depth paths or cycles and states are not tracked with a visited collection.
